# Data dictionary

This summarizes current contracts; the [Protocol v5 Markdown](../protocols/experiment_protocol.md) defines the method. The PatchPrompt CSV is a candidate index, not a complete case source. Its `PR_Size` column is inherited metadata and unused for DIR screening.

## Screening

Stage A records are `dir-screening-v9` under `dir-tfg-v2`, written to distinct `screened_PA_PN_cases.csv` and `eligible_PA_PN_cases.csv` paths. `case_id` is stable; `source_case_id` links to the index. `Outcome_Class` selects the PA/PN population and later split strata, but is not a retrieval cue. `source_linkage_status` records administrative linkage as `established`, `conflicting`, or `unresolved`, with separate provenance and reason. `pr_conversation_match` records the separate Stage A manual judgment as `yes`, `no`, or `unresolved`, with reviewer provenance; it directly contributes to scientific eligibility. `conversation_available`, `temporal_anchor_available`, `first_generation_boundary_identifiable`, `duplicate_status`, `project_history_accessible`, and `historical_state_reconstructible` describe processability. `eligible` is `true`, `false`, or blank pending resolution; `eligibility_status`, `exclusion_reason`, `pending_reason`, and `processability_source` explain the scientific judgment. `stage_b_readiness_status` is separate operational metadata. A pending case may be `ready_for_stage_b` only when all packaging prerequisites pass and its pending reasons are limited to `first_generation_boundary_identifiable_unresolved` and `historical_state_reconstructible_unresolved`; any other pending reason blocks it. `stage_b_readiness_reason` records either `scientifically_eligible`, `pending_only_stage_c_tfg_deferred`, or explicit blockers. `changed_files`, `additions`, `deletions`, `changed_lines`, `pr_commits`, developer prompts, and conversation words are descriptive and cannot exclude by magnitude alone.

### Required and complementary Stage A fields

Revised Word Protocol v5 §2.3 requires the neutral Case ID (`case_id`), PR URL/identifier (`pr_url`, with `repository`/`pr_number`), conversation reference (`conversation_url`), outcome class (`Outcome_Class`), conversation availability (`conversation_available`), temporal-anchor availability (`temporal_anchor_available`), preliminary boundary identifiability (`first_generation_boundary_identifiable`), PR/conversation match (`pr_conversation_match`), duplicate status (`duplicate_status`), project-history access (`project_history_accessible`), eligibility/status (`eligible`, `eligibility_status`), and exclusion reason (`exclusion_reason`). Stage A's boundary field records preliminary processability, not the authoritative first-generation `tFG` determined in Stage C. Existing retrieval/parsing statuses, precision/status/source, pending and provenance reasons, descriptive measures, and `stage_b_readiness_status` are complementary operational fields. None adds a numerical eligibility threshold.

`cases/manifests/case_mapping.csv` is a restricted researcher-only mapping derived from the authoritative source index and the current Stage A screened rows. Required Word fields are `case_id`, `pr_url` (PR identifier), and `Outcome_Class` (PA/PN). `mapping_schema_version`, `source_case_id`, `conversation_id`, and `conversation_url` are complementary provenance fields. It does not replace `linkage/*.json` and is never Stage C model input. Stage A may access PR/project identity for administrative integrity, mapping, accessibility, duplicates, and processability; substantive project-evidence inspection waits until Stage E freeze.

`dir-source-linkage-correction-v1` records a verified correction to an inherited PR/conversation association without modifying the inherited source CSV. The overlay preserves the original and corrected URLs/IDs, stable case/source/PR binding, reviewer, timestamp, version, reason, and evidence reference. Current Stage A mapping and Stage B selection apply verified overlays before resolving conversation identity; historical reviews remain preserved separately.

## Conversation and temporal records

The current conversation-only package is `conversation-only-v1` with methodology `dir-tfg-v2`. It contains neutral case ID, temporal source, complete ordered visible turns, artifact candidates, and stable provenance. Project/outcome metadata is absent by contract. Supplied Context, Specificity, and Verification are source-supported information categories, distinct from inherited numerical `C_score`, `S_score`, and `V_score`.

For Protocol v5 records, `procedure_validation_status` describes whether the extraction procedure passed sample validation. `case_human_validation_status` distinguishes sampled human validated, sampled adjudicated, not sampled, and unresolved cases. `case_extraction_status` and `case_boundary_status` describe each case separately; `case_processability_status` records the structural check. `record_status = frozen` means an immutable output of the validated procedure, not individual human review.

`case-linkage-v2` is restricted administrative metadata keyed by neutral `case_id`; it retains PR and source-conversation identity, including the Stage A canonical PR URL. It snapshots the established source-linkage and positive correspondence authorization used for packaging and references the authoritative Stage A manifest row and canonical correspondence-review JSON. Review rationale and evidence remain owned by Stage A. The linkage is not Stage C input. `chatgpt-source-v1` retains source payload bytes (base64), source SHA-256, source URL, retrieval time/status, and allowlisted HTTP metadata without request credentials. `lossless-conversation-v1` retains original parsed records, tool/other traces, raw conversation structure, visible turns, artifact candidates, and source positions. `conversation-only-v1` is the derived Stage C model view; it excludes administrative/project metadata and tool-directed source records from supplied-C/S/V context. See protocol §2.
The source archive records `source_origin` (`fresh` or `cached`) and `retrieval_time_status`. HTTP cache entries retain their actual retrieval timestamp when known; entries without one use `unknown_legacy_cache` and a blank `retrieved_at`. `stage_b_status = complete` means the archive checksum, normalized ordering/source positions, and allowlisted model view passed validation. `retrieval_failed`, `normalization_failed`, and `validation_failed` remain distinct incomplete outcomes.

`tC` (first developer prompt) and `tFG` (boundary immediately before the first artifact-bearing assistant response in the first snippet family) retain independent value, precision, status, and source. Current `primary_repository_cutoff` is `tFG`. Missing `tFG` is never filled from `tC`; date-only values do not become exact timestamps. `available_by_tC` and `available_by_tFG` remain separate (`YES`, `NO`, `UNCERTAIN`, `UNAVAILABLE`). Historical availability alone is not retrieval, relevance, or additional evidence.

The stable Stage A screening, researcher-only mapping, and Stage A manual correspondence-review records have versioned contracts and explicit CSV-to-logical-record validation. The earlier conversation and repository-evidence JSON schemas remain legacy `dir-tfg-v1` contracts; they do not validate current Protocol v5 downstream records. See [schemas/README.md](../schemas/README.md).

`case_integrity_status = ok` means only that implemented structural, identity, and duplicate checks found no conflict; it does not imply semantic correspondence. Stage A stores the identity-bound judgment in `cases/manifests/correspondence_reviews/<case_id>.json` for candidate/processable cases reaching manual screening. An index pair or archive association can establish source linkage but cannot automatically establish semantic correspondence. `project_history_accessible` is determined by a separate Git commit-object probe; `project_history_access_*` records mechanism, repository, tested object, status, source, and reason. The fetch permits up to 900 seconds, and a timeout is recorded explicitly as unresolved `fetch_timeout`. PR API accessibility is distinct from Git history accessibility. A successful Git probe does not prove `historical_state_reconstructible` at authoritative `tFG`.

The intermediate `stage_a_correspondence_review.csv` has stable identity, linkage, automated-status, evidence-policy/reference, judgment, and six manual provenance columns. Researchers edit only the judgment and six `pr_conversation_match_*` provenance columns. Blank judgments produce no canonical JSON and remain unresolved. Initial exports use `identifiers_and_source_linkage_only`. Completed semantic reviews may be prepared under `direct_share_reference_and_restricted_task_context_v1`, which binds each row to a checksum-verified `dir-correspondence-evidence-v1` packet under `cases/manifests/correspondence_evidence/`. Packets retain only an identity-bound PR share reference, minimal developer-authored task context, archive provenance when available, and the review observation. They explicitly distinguish archive support from reviewer attestation and are never Stage B/C input, Stage G input, or reconstruction evidence.

`conversation_turn_pattern` is derived only from the count of developer turns in a complete parsed conversation (`single_developer_prompt`, `multiple_developer_prompts`, or `unavailable`). It is descriptive and affects no Stage A decision. The v9 scientific manifest omits the former pilot lexical signals, cue lists, unassessed qualitative placeholders, and their producer provenance. Historical v6 outputs retain their original meaning and are not v9 records.
