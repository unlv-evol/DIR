# Reproducibility

The authoritative repository protocol is Protocol v5.2 (`protocols/Developer_Intent_Reconstruction_Experiment_Protocol_v5_2.docx`). It uses methodology `dir-tfg-v2` and current screening schema `dir-screening-v9`. Record source CSV checksum, stable case/source IDs, retrieval and parsing status, processability source, methodology/schema versions, validation and freeze versions, split seed/stratum/assignment once defined, code commit, configuration version, source artifact IDs, both temporal anchors and their precision/status/source, the authoritative `R_i(tFG)` identity and derivation references, and checksums for frozen outputs. Record model/version and generation settings at generation time.

Stage A intermediate outputs use `data/intermediate/screening/`; methodology and schema versions are recorded in the outputs. Preserve acquired source material and retrieval provenance. Do not silently overwrite existing research outputs or frozen records. Reproduce SAFE inputs without exposing SEALED future or outcome information. See [the protocol](../protocols/experiment_protocol.md).

Within Stage A, record source-linkage provenance separately from manual semantic correspondence. Preserve one versioned `dir-correspondence-review-v1` record for every candidate/processable case reaching manual screening; verify identity binding before finalizing eligibility. Stage D remains the approximately 30% extraction-validation sample.

The deterministic `stage_a_correspondence_review.csv` is a restricted interchange artifact. Preserve its `dir-correspondence-review-csv-v1` version, evidence policy/reference, and manual provenance during import. Canonical per-case JSON remains authoritative; identical re-import is idempotent and conflicting records fail closed.

For semantic reviews, preserve the checksum-bound `dir-correspondence-evidence-v1` packet referenced by both CSV evidence-reference fields. Retain its support status rather than treating reviewer attestation as archived proof. These packets are Stage A administrative records and cannot be reused as reconstruction evidence or retrieval input.

Validate Stage A CSVs by checking exact headers, explicitly parsing blank/boolean/integer/temporal cells into logical records, then applying the versioned contracts and cross-field checks in `schemas/` and `src/developer_intent/stage_a_contracts.py`. `pipeline/screening/validate_contracts.py` validates existing outputs without retrieval. A blank eligible field for `pending_resolution` remains null, not false; an explicit `unresolved` judgment remains unresolved.

Retain restricted PR/conversation review records with reviewer, method, time, version, rationale, and evidence reference. Retain Git history access mechanism, tested repository/commit, result, and failure reason separately from PR API retrieval and later historical-state reconstruction.

Reproduce Stage B readiness from explicit Stage A prerequisites rather than scientific status alone. A ready pending row must contain only the two versioned deferred reasons for preliminary boundary identifiability and `tFG`-dependent historical-state reconstructibility. Preserve that pending disposition through Stage B. The strict resolved-case gate is applied immediately before Stage E freeze and downstream assignment.

The restricted `case-linkage-v2` record identifies the exact Stage A manifest row that authorized packaging, snapshots established source linkage and positive correspondence, and references the canonical correspondence-review JSON. Treat those references as the authoritative provenance; do not pass the linkage or review material to Stage C. Stage B HTTP acquisition reuses a complete body-and-metadata cache entry unless `--refresh` is supplied. `--live` permits acquisition when cache data is absent; it does not force a network refresh.

Legacy raw responses are admitted only through the explicit offline import path. Require the original `.body` and paired metadata, recompute the canonical public cache key, validate public status, HTTP 200, and conversation identity, then reparse with the current parser. Preserve raw bytes and SHA-256, legacy paths and metadata, null retrieval time with `unknown_legacy_cache`, and a separate timezone-aware `imported_at`. Never infer retrieval time from file metadata or silently substitute derived evidence JSON or parsed-cache output for missing raw bytes.

Archived historical HTTP responses are admitted only through the explicit offline ZIP import. Verify the archive checksum, exact share ID and PR association, HTTP 200, nonempty `HTMLContent`, and current-parser completeness. Select the earliest qualifying archive filename timestamp, breaking ties lexically by member and then source/sharing indexes. Preserve every qualifying candidate plus ZIP/member/HTML hashes. Preserve timezone-naive `DateOfAccess_raw` verbatim while keeping `retrieved_at = null` and `retrieval_time_status = unknown_archive_timezone`. Never substitute `Conversations`, screening evidence, correspondence material, or parsed cache output.

Preserve valid packages before considering any source. Corpus materialization checks current cache and then validated legacy cache. Archived HTTP recovery is a separately authorized explicit operation rather than a silent fallback. Record `fresh`, `cached`, `legacy_cache_import`, and `archived_http_response` without collapsing their provenance classes.

Validate Stage B isolation by rebuilding the model view deterministically from the normalized conversation and requiring exact equality plus the allowlisted top-level contract. Do not use administrative-value substring absence as proof of isolation: a matching repository or PR string in preserved conversation text retains conversation provenance. Any independently added field or text mutation fails the deterministic comparison.

For Stage B V2, rebuild `conversation-only-v2` from the immutable `lossless-conversation-v1` record with producer `generated-technical-content-v2`. Validate each `GTC_*` ID by recomputing it from response event, inclusive/exclusive Unicode offsets, and the exact raw-text SHA-256; also validate complete-turn hashes, substring equality, response ownership, canonical ordering, unique spans, and exact nullable V1 mapping. V1 files and Stage C outputs remain immutable. Use `pipeline/extraction/build_v2.py` with a `/tmp` output directory for a controlled single-case check. Run `python3 -B pipeline/extraction/materialize_v2_corpus.py --validate-only` to reproduce corpus validation and the in-memory V1/V2 impact comparison without writing. The authorized corpus materialization command is `python3 -B pipeline/extraction/materialize_v2_corpus.py --materialize`; it creates missing canonical V2 views and the versioned JSON, CSV, and Markdown migration reports, and refuses to overwrite an existing report or a V2 view that differs from the deterministic producer.

Stage C Pass 1 prompt v3 returns a response-local semantic selection plus a descriptive `family_label`, not canonical identity. After validation, order selected artifacts by `(response_event_index, order_within_response, artifact_id)`, serialize `{"artifact_ids":[...],"case_id":"..."}` as compact key-sorted UTF-8 JSON, hash it with SHA-256, and use `FGF_` plus the first 24 lowercase hexadecimal digest characters. Later-response candidates do not enter this canonical input. The case ID provides global rather than case-local identity. Preserve the full digest and canonical input in provenance. Deterministic migrations from v2 retain the immutable original output, its hash, original model family value, and unchanged model provenance.

This algorithm is frozen as part of `conversation-draft-v3` / `conversation-extraction-v3`: `FGF_<24 lowercase hexadecimal characters>`, with the characters taken from the first 24 positions of that SHA-256 digest. Subsequent pilot waves must use it unchanged. A demonstrated methodological defect requires a new explicitly versioned contract rather than an in-place algorithm change.
